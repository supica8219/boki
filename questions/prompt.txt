問題を以下の形式に基づき作成してください。

【重要】
この問題セットは「解説教材」ではなく、
「1問ずつ理解しながら解けるUI用クイズ」です。

問題は必ず、
「今この画面だけで解ける」
「1問1理解」
「1問1計算」
になるよう作成してください。

────────────────────
【最重要ルール】
────────────────────

このUIは以下の形式で動作する。

- choice = 選択問題
- input = 仕訳問題

input問題では、
「科目ごとに借方・貸方へ金額入力するUI」
を使用する。

つまり、

accounts に並んだ科目に対して、
借方・貸方のどちらへ、
choices の金額を入力する形式。

そのため、

input問題では必ず
「どの科目にどの金額を入れるか」
が明確になる問題を作ること。

文言は体言止めで完結に書く。
仕訳問題の形式の場合、同じ科目が複数行登場しないようにしてください。 登場する場合合算値とするように
────────────────────
【問題設計ルール】
────────────────────

1. 問題は1画面完結にする
- 前問の情報を前提にしない
- 必要情報はdescに必ず再掲
- 問題単体で解けるようにする

2. 問題は細かく分解する
- 一気に完成形を問わない
- 中間計算を問題化する
- 解く順番で出題する

例：

悪い：
「完成品原価はいくら？」

良い：
「単価を求める」
↓
「月末仕掛品原価を求める」
↓
「完成品原価を求める」

3. commentは理論説明禁止
- 解き方だけを書く
- 今その問題をどう解くかだけを書く
- 背景説明は禁止

────────────────────
【commentの書き方】
────────────────────

commentは必ず以下順で書く。

1. なぜその計算になるか
2. 計算式
3. 答え

良い例：

comment:
"平均法なので原価合計を数量比で配分する。<br>
まず単価を求める。<br>
1,102,500 ÷ (30,000 + 1,500) = 35円/kg<br>
次に月末仕掛品数量を掛ける。<br>
35 × 1,500 = 52,500円"

悪い例：

comment:
"正常減損は完成品負担であるため〜"

→ 理論説明なのでNG

────────────────────
【comment禁止事項】
────────────────────

以下は禁止。

- 「理論上」
- 「〜という考え方」
- 「簿記では」
- 「原価計算では」
- 「通常は」
- 長い背景説明
- 教科書的説明
- 概念解説

────────────────────
【input問題の重要ルール】
────────────────────

input問題は、
「仕訳UIに入力する問題」

UI構造：

- 勘定科目一覧(accounts)
- 借方列
- 貸方列
- 金額候補(choices)

ユーザーは、
各科目へ借方・貸方の金額を入力する。

そのため、

input問題では必ず：

1. 科目が不足しない
2. choices金額が不足しない
3. answerがUI構造に一致する
4. 借方・貸方が明確
5. descで何を入力するか明示する

────────────────────
【input問題の良い例】
────────────────────

{
  type: "input",
  question: "差異振替仕訳を入力しよう",
  desc: "製造間接費配賦差異9,000円（借方差異）を予算差異と操業度差異へ分解する",
  comment: "借方差異9,000円を分解する。<br>操業度差異10,000円を借方へ入力する。<br>製造間接費配賦差異9,000円と予算差異1,000円を貸方へ入力する。",
  accounts: [
    "操業度差異",
    "製造間接費配賦差異",
    "予算差異"
  ],
  choices: [0, 1000, 9000, 10000],
  answer: [
    { key: "操業度差異", side: "借方", amount: 10000 },
    { key: "製造間接費配賦差異", side: "貸方", amount: 9000 },
    { key: "予算差異", side: "貸方", amount: 1000 }
  ],
  hint: ["差異振替", "操業度差異", "予算差異"]
}

────────────────────
【input問題で必須】
────────────────────

choicesには必ず0を含める。

理由：
未入力セル用。

例：

choices: [0, 1000, 9000, 10000]

────────────────────
【descのルール】
────────────────────

- 数字を整理
- 行分けする
- 必要情報だけ
- 長文禁止

────────────────────
【出力形式】
────────────────────

必ず以下のみ出力。

window.questionsData = [
  {
    ...
  }
]

余計な説明は禁止。

────────────────────
【問題オブジェクト仕様】
────────────────────

type:
"choice" or "input"

question:
問題タイトル

desc:
問題本文（HTML可）

choices:
選択肢

answer:
正解

accounts:
input形式の科目一覧

comment:
解き方のみ

hint:
補助ワード

────────────────────
【UI目的】
────────────────────

目的は、

「教科書説明」ではなく、

"その問題を今解けるようにする"

こと。

commentは常に、

「次も同じ問題を解けるようになる説明」

を書く。
